# 通知邮件格式与运行说明

更新：2026-11-24。格式决策见[邮件通知系统计划](../EMAIL_NOTIFICATION_PLAN.md)。管理员试用已确认 QQ 邮箱不支持原先的 `multipart/multilingual`，现改为用户选择通知语言，每封发送单语正文。

## 语言设置

`UserProfile.language` 支持 `zh-cn`、`en`、`es`，默认 `en`。现有账号通过迁移初始化为英文，新账号同样默认英文；设置与网站界面语言独立，不根据浏览器语言自动改写。

本人主页设置 tab 提供项目原生选择框，语言与订阅位随已有登录响应返回。`PATCH /api/userprofile/email-notifications` 可只传 `{language: "es"}`，或与 `changes` 一并保存；省略的偏好保持原值。非法语言拒绝整个更新，不会部分写入订阅位。

普通用户也可以保存语言和管理员通知订阅位；管理员通知类型只在前端向管理员显示，实际收件资格在 worker 发信时检查。偏好不进入公开用户资料或玩家缓存。

## 邮件格式

复用 Django 的 `EmailMultiAlternatives`、现有 SMTP 后端及统一额度入口，不重写 MIME 序列化方法：

```text
Subject：接收方所选语言的通知标题
Content-Language: zh-cn / en / es（仅所选的一种）
multipart/alternative
├── text/plain：所选语言的正文及链接
└── text/html：同一语言的正文及链接，HTML lang 与语言一致
```

worker 查询收件人时读取当前保存的 `language`，任务参数只保存通知类型与对象 ID。排队期间改语言，会在实际执行时生效。一封邮件一个收件人，只占一封额度；不再携带其他语言版本、三语前言或嵌套 `message/rfc822`。

主题、数量标签、后台入口和本人设置链接均本地化。仅提供必要类别、数量与对象 ID，不发送不安全标识原文，不自动翻译用户内容。HTML 继续使用 Django 模板转义，链接仍需网站登录及权限验证。

## 运行与部署

- 通知随全站邮件开关 `EMAIL_SKIP` 启用：`False` 时入队并发送，`True` 时入队和 worker 执行都会跳过。`E2E_TEST` 为真时也跳过。
- `EMAIL_QUOTA_TIME_ZONE` 默认 `Asia/Shanghai`（UTC+8），已按确认的供应商时区设置；不受项目或浏览器时区影响。
- `EMAIL_WEBSITE_URL` 默认 `https://openms.top`，用于生成后台与本人设置链接。
- `EMAIL_DAILY_LIMIT` 为 2000，通知和验证码共用单条 `EmailSentQuota` 当前日期记录；失败不退额，不保存历史日期。
- 请求只在事务提交后写入任务，不查询收件人、占额或等待 SMTP。发送使用现有 `db_worker`，按当前角色、订阅和对象状态筛选；一次尝试后结束，不补发。

部署与 CI 沿用现有自动生成迁移流程；本地已自动生成 `language` 字段迁移用于校验，不单独提交依赖本地历史链的迁移文件。部署时先生成并应用迁移，再恢复网站与 worker。订阅默认全部关闭。

首次启用邮件额度保护时，需在服务恢复前初始化供应商当日已用量，或在新的供应商额度日期开始启用；后续重启不得清零。初始化步骤见开发文档的数据库迁移章节。本次语言更新不重置额度。

## 验证范围

自动测试使用内存邮件后端，验证三种语言的主题、UTF-8 纯文本与 HTML、语言标签、链接、仅有单语正文，以及 worker 使用发送时偏好；不发送真实邮件。

原方案的 QQ 不兼容结果来自管理员试用。新格式仍需管理员在 QQ 及其他实际客户端验收主题、HTML/纯文本和后台链接；自动序列化测试不代表真实投递已验证。
