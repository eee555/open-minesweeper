# 国际化文档

本文档说明前端项目的多语言结构和命名约定。如果不确定如何新增语言，请联系维护团队。

## 基本结构

i18n 相关代码位于 `src/i18n`：

- `src/i18n/index.ts`：创建 `vue-i18n` 实例，注册全局语言包。
- `src/i18n/locales/*.ts`：各语言的全局文案。

网站、离线小游戏和离线录像分析器均注册 `src/i18n/index.ts` 提供的 i18n 实例，完整打包已注册的全局语言资源；组件内的局部文案随组件一起打包，不额外维护离线语言资源子集。

当前全局语言包注册了 `dev`、`zh-cn`、`de`、`en`、`pl`。`dev` 不包含正式文案，仅用于定位缺失 key。`fr.ts` 文件存在，但当前没有在 `src/i18n/index.ts` 中注册到全局 messages。

## fallback 规则

fallback 配置位于 [src/i18n/index.ts](../src/i18n/index.ts)：

新增任何文案时，至少提供 `zh-cn` 或 `en`，方便后续补译。

## 全局文案

可复用、跨页面或跨组件的文案放在`src/i18n/locales`中，例如菜单、通用按钮、通用错误消息、用户资料字段等。

全局 key 直接按用途分组，例如 `button.cancel`、`prop.time`、`level.b`、`minigame.title`，不再增加 `common` 外层。组件私有文案统一放在 `local.*` 下，由此区分局部与全局。

## 组件局部文案

只在单个组件内使用、复用价值不高的文案，可以直接放在组件内的局部 messages 中。项目惯例是把局部 key 放在 `local` 下。已有示例可参考 [src/components/ExperimentalFeature.vue](../src/components/ExperimentalFeature.vue)。

局部文案建议至少提供 `zh-cn` 或 `en`，方便后续补译。

## 通过插值复用文案

相同含义的固定文案直接调用全局 key，例如 `t('button.cancel')`，不增加 `local.cancel: '@:button.cancel'` 这样的整体别名。没有局部文案时，组件直接使用 `useI18n()`。

句子需要组合已有词语时，使用 Vue I18n 的消息链接：

```ts
const i18nMessages = {
    'zh-cn': { local: { saveHint: "修改后点击“@:{'button.save'}”。" } },
    en: { local: { saveHint: 'Click @.lower:button.save to apply your changes.' } },
};
```

只差数量、间隔等参数的句子使用命名插值，例如 `statistics.cache` 中的 `{minutes}`，调用 `t('statistics.cache', { minutes: 5 })`。复合消息中的链接也会将参数传给被链接的消息。整句保留各语言独立的语序，不在代码里拼接翻译后的句子片段。

引用后紧跟中文等字符时，用字面量限定 key，例如 `"@:{'form.email'}验证码"`，避免后面的文字被误读为 key。英文需要调整大小写时可使用 `@.lower:form.password`；仅在文案含义相同的情况下复用，不将不同业务状态仅因当前文字相同而合并。

两个离线入口复用全局 i18n 配置，组件可以直接使用全局 key 和消息链接；语言资源模块保持独立于网站请求、状态和路由。消息链接、命名插值及大小写修饰符见 [Vue I18n 消息语法](https://vue-i18n.intlify.dev/guide/essentials/syntax)。

## 放置规则

- 多处复用的文案放全局语言包。
- 只在一个组件出现的文案放组件局部 messages。
- 表单字段、状态名、通用错误消息优先放全局语言包。
- Cypress测试中无需考虑多语言，但是需要注意：组件测试会渲染英文，而端到端测试会渲染中文。
- 组件局部 key 使用 `local.*`，避免和全局 key 混淆。

## 翻译检查清单

提交涉及文案的改动前，建议确认：

1. 至少有 `zh-cn` 或 `en` 文案。
2. 有局部文案时使用 `useI18n({ messages: i18nMessages })`；全部使用全局 key 时使用 `useI18n()`。
3. 文案 key 命名表达业务含义，而不是表达当前显示样式。
4. 没有把可复用文案散落在多个组件局部 messages 中。
