## 独立资源

正式源资源目录为 `front_end/src/assets/medal-overlays/difficulty/`，含三张 PNG、`manifest.json` 和使用说明。此处 `resources/` 的 PNG 为同一原始生成结果的逐字节副本，便于本地审阅服务下载；校验值见生成记录。三个独立资源只通过内置 imagegen 生成，未用代码抠图、重绘或组合星星。

各资源保留共同方形画布：一星位于下排中央，二星位于下排两侧，三星在两颗下排星上方增加一颗。不能分别按有色区域裁切后等宽显示，否则单颗星大小和上下位置会变化。三组均通过整张方形画布缩放与主体叠加。

## 统一位置提案

本轮位置为待检阅提案，不冒充用户已认可整体比例。以 320×320 为统一视区：

- 星级盒 `(x=0, y=0, w=115.2, h=115.2)`，即左上角 36% 方形区。
- 主体盒 `(x=67.2, y=67.2, w=252.8, h=252.8)`，即左上各内缩 21%，宽高 79%。主体先按 alpha 边界裁切、等比适配并居中放入方形底图，再置入主体盒。
- 星级颜色独立于成绩配色，NF 副章随主体保留，不与星级共享角标槽。

直接沿用 time 旧图的留白，会遮到通明的放射光芒与精工结构。因此先为所有系列保留同一角标区，主体采用一致的显示区；不逐个难度改变主图大小。最初 80% 主体在 32px 下与盲扫通明三星发生一像素重叠，调整到 79% 后检查通过。

各尺寸将位置与大小分别四舍五入到像素。检查以 alpha > 32 为有效像素，覆盖 32／40／48／64／72／320px：8 类 × 3 难度 × 6 尺寸，共 144 项均无有效像素重叠。检查使用 128px WebP 试导出，放大审阅另外使用 320px PNG，避免放大低分辨率底图。32px 中星形细节有限，仍需连同正文难度文字验收。

## 全部单难度称号的适用规则

现有源图实际覆盖 8 类、24 种组合：破境、神速、通明、盲扫破境、盲扫神速、盲扫通明、盲扫精工、标旗精工。源定义核对 `back_end/saolei/medal/utils.py` 的 `basic_definitions()`，称号语义核对 `docs/medal/称号方案.md`。

后续所有明确属于单一初／中／高级的称号共享这套标记与位置，包括各难度概率收集、上限收集、BV 种数、达标局数、薄盘、数字收集、中级时亚速、初级一 BV，以及金羊杯单局与有效最佳的各难度名次。尚无本套主体源图的未来类别，只完成适用规则和角标区约束，不宣称已经做完其美术与位置验收。

必须从定义或统一外观配置获取单一难度，不扫描称号里的“初／中／高”来推断，也不只凭 code 尾缀判断。三阶精工、三级合计、中高级合计和跨难度交叉比较表达多个难度，不自动标成高级三星；新手、关联、资历、纪念及赛事总名次等无单一难度的称号不加标记。赛事金属依然独立表示名次。

## 资源与后续接入

`build_review.py` 使用既有发布流水线生成 `bodies/` 的 8 张独立主体试导出，并通过图层在 HTML 和展示图中组合，不将星级烘焙进主体源模板或单独批量保存 24 张成品。主体试导出遵守现有 128×128 WebP 编码与单图预算；资源区另提供三张 64×64 星级 WebP 试导出，保留全画布和 alpha。

当前只保存共享源资源、位置提案、适用规则及检阅预览，尚未接入 `MedalArt.vue`、正式发布图、成绩配色或发放规则。后续接入时让所有展示入口共享同一难度映射与布局配置，并为新增主体补做重叠及小尺寸检查。
