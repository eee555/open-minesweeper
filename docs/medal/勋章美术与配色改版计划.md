# 勋章美术与配色改版执行计划

状态：2026-11-01 用户授权将新图形、已确认的柔和金属配色接入所有现有初／中／高级能力勋章，并更新本地网站、生成生产部署包。已实现 24 个单难度定义的明确成绩色档、共享模板着色、CSS 数字和自主配色入口；保留三阶与其他无单一难度称号的独立规则。

重做勋章的图形语言，使不同系列在小尺寸下也有鲜明特征，并将能力勋章的颜色从「初级铜、中级银、高级金」改为表达成绩档次。页面布局与操作见[勋章界面改版执行计划](./勋章界面改版计划.md)。

用户已明确要求尽可能保留原勋章的核心部分，v1 过度简化的抽象图标方向弃用。后续以原图主体、组合关系和勋章质感为基础，优先收减背景、多重外圈、碎片与光效；不能为了简约改成另一种象征物。原图识别与传承优先于扁平化或矢量格式。

首次实施只制作全部现有系列的基础模板及检阅预览，完成后提交给用户并等待明确同意。用户同意前不制作正式成绩配色与门槛映射，不替换现有资源，不改造正式渲染组件，也不接入勋章页面、个人资料栏或名字提示。下文的图形方向和候选色板均为提案，不视为用户已认可。

## 问题与设计目标

当前勋章共用较重的金属外圈、网格背景、高光和装饰，缩小后外圈比核心图案更显眼，破境、神速、通明等系列难以快速区分。`medalArtMetal()` 直接从勋章 code 的难度后缀取色，导致不同成绩档位的高级勋章都呈现金色。

现有展示尺寸为勋章页 72px、个人资料栏 48px、玩家名字提示 32px。改版另有 32 至 40px 的行内档位节点和 64 至 72px 的行首主图。以 32px 为起点设计，在 32、40、48、64、72px 验收。放大图只用于检查细节，不作为辨识度合格的依据。

## 参考页面的美术启示

视觉依据为用户提供的两页 B 站勋章 PDF，来源及核对范围见界面计划。参考页将同一系列的多个档位同时并列，小图下直接写门槛，部分系列通过颜色或简单轮廓变化建立关联。本站也应让一个系列在并列时看起来属于同一家族，让不同系列在混排时容易区分。

采用这一展示关系，同时遵守本次「更简约」的目标。参考图中高档勋章存在增加羽翼、花边等做法，本项目不随档次不断堆叠装饰。跨成绩档优先复用同一主符号，通过色档和门槛文字表达变化；系列识别依赖图形，档次识别依赖颜色与文字。

参考页的「普通勋章／高级勋章／稀有勋章」是其类型文案，不等同于本站初／中／高难度或成绩档次，不直接移植。

## 图形与信息分工

- **系列由原图核心表达。** 保留原图主体的形状、方向和组合关系，适当放大并清理周围噪声，保持不同系列可辨。
- **玩法沿用原图识别方式。** 保留已有禁旗圆形副章；三阶保留三个圆章的组合，新秀保留有旗／无旗雷盘差异。补充文字标签，不统一改成新的角标系统。
- **难度由独立星级与明确文字共同表达。** 初级一颗星、中级两颗星、高级三颗星，三星为上方一颗、下方两颗的三角排列。星级保存为三张共享透明资源，在左上角由展示层叠加；不烘焙到各系列主体。页面保留「初级／中级／高级」与完整可访问名称；三阶及跨难度称号不自动视作高级三星。
- **成绩档次由默认五色色板、色档编号和门槛文字共同表达。** 不能仅凭颜色判断档次或精确成绩；用户可按个人视觉需求自定义颜色，编号与门槛保持可读。
- **获得和佩戴由界面状态表达。** 未获得采用中性处理，佩戴与待保存选择使用独立勾选或边框标记，避免冒充某一成绩档次。

行内阶梯会同时展示已达与未达档：未达节点可以保留低饱和的目标色供比较，但必须标「未达成」；行首未获得主图使用中性处理。目标预览不应用已佩戴标记，当前档标记也不烘焙进图案。

## 简约美术规范

保留金属边框、珐琅底色、适度切面与厚度，让成品仍然具有原勋章的质感。精简优先发生在多重外圈、背景密网格、细碎飞片、过密放射线与强泛光；主体所必需的雷盘格线、胶片齿孔、文件卡等结构仍需保留。

边框收敛为适量层次，降低它对主体的遮蔽。主图适当放大，保留必要的明暗与负空间。小尺寸重点检查主轮廓、主体数量与玩法区分；不强求原图全部纹理在 32px 下可见，也不将微小细节硬描成大量矢量路径。

用户已同意破境、神速、三阶精工与原始股东四枚去外框样例，并明确要求扩展其余系列：移除统一的大圆框、四方装饰尖角与共同圆形背景底板，保留主体金属边缘和厚度。三阶精工的内部三枚圆章、禁旗及审核副章、档案盒蓝色侧面等属于主体，继续保留。全套 17 枚现已获用户同意，并按“保存为模板，替代之前的模板”替换正式源模板；本次授权不包含正式成绩配色或页面接入。

v2 按原图采用以下方向，后续修改也以此为基础：

- 破境：穿破圆章的上升折线箭头，保留折线走势与方向。
- 神速：弧形速度轨迹和分离尾迹，保留流动的扫掠构图。
- 通明：中心发光方格与放射光芒，保留方格这一核心。
- 精工：中心方格、四向内聚箭头和分段目标圆环。
- NF 与三阶：保留禁旗圆形副章；三阶保留一上两下的三枚方格光芒圆章，收减各自花边。
- 实名与过审：分别保留竖向折角证件与胶片播放框，以及各自的圆形审核勾章。
- 新秀：保留三层递进雷盘与红旗；盲扫新秀沿用三层无旗雷盘。
- 多模式：保留六面环绕雷盘及蓝色格子。
- 旧迹新篇：保留旧雷盘窗口、迁移箭头与蓝色站点徽标。
- 原始股东：保留档案盒、前金后蓝的历史记录卡与站点徽标。

这些是制图起点。若辅助标记在 32px 下不能辨识，应调整构图或使用独立小尺寸版本，不能只靠悬浮文字弥补图形混淆。

## 成绩档次与配色

### 颜色方案

2026-10-31 用户反馈前两轮默认方案的颜色区分不足，最新改为深蓝 `#244A86`、中蓝 `#4C91C7`、浅紫 `#CCB8E3`、浅橙 `#F2CE9B`、中红 `#B34A55`。拉开蓝色之间的明暗差，将紫色提亮、橙色调暖，中红保持较深的明度；不再要求五档基色亮度逐档递增。色相与明暗共同辅助区分，成绩顺序始终由色档编号与门槛文字表达。

使用红、绿、蓝色觉缺失模拟检查基色，不能保证所有用户都能只凭颜色辨认。色档编号、完整称号与 Sub／数值门槛常驻，参考 [W3C 用色指南](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。

最新[五色平衡方案与自定义离线审阅页](./artwork-drafts/time-color-accessible-v5/exports/time-color-accessible-preview-offline.html)支持五档独立选色、单门槛覆盖、恢复默认、本地保存及 JSON 导入导出。默认色板与初级门槛分组均待审阅。

未获得使用独立中性色。一次性新手、关联、纪念勋章使用固定主题色，不因只有一档就自动成为最高色档。原始股东按其三档资历另设映射；赛事金银铜等已有名次含义的类别保持独立规则，不套用能力配色。

### 档次映射规则

能力配色根据「系列、玩法、难度、已授予门槛」查找明确的视觉档次。初、中、高可以使用同一组颜色，但分别按自己的门槛分组：初级的较高成绩档也可以呈现高档色，高级的起步成绩不会天然呈现最高色。

先为现有十个能力系列及其难度编制完整映射清单。执行时依据 `thresholds` 的实际内容与项目已有成绩档位讨论分组，产出每个 code 下各门槛对应的 `tier`，再接入组件。五档是建议起点；较短阶梯可以使用其中部分颜色，不要求每一条阶梯都填满五档。

分组需要遵循：

- 同一定义中越难的档位，视觉档次不下降。同一色档可以覆盖多个相邻数值门槛，精确差别由数字表达。
- `stage` 是达标门槛值，不是第几档。时间类越小越好，其他指标通常越大越好，不能直接按原始数值大小统一取色。
- 不直接用 `stage / stage_count`、阈值序号等分或「到达本系列最后一档」推导跨系列水平；现有各阶梯长度和难度分布不同。
- 同一颜色只表示设计中对应的成绩层次，不宣称相同百分位、相同排名或严格相同的跨指标能力。不读取排行榜来决定颜色。
- 不为了凑齐颜色档改变发放门槛。映射中遇到尚未覆盖的新门槛时回退到中性色，并在开发检查中报告，避免误显示最高档。

第一轮对照必须包含初／中／高三个难度各自的低、中、高成绩，以及 NF／FL 精工和三阶的短阶梯。具体门槛边界在执行中的映射清单里给出，本计划不将尚未核定的颜色边界写成新的成绩标准。

## 资源与渲染方案

当前采用 imagegen 编辑原位图得到的 v3 去外框透明 PNG。17 枚已获同意，并原样保存到 `front_end/src/assets/medal-templates/`；三阶标旗精工由 JPG 改为 PNG，旧源图已备份。生成器直接保留 alpha，维持现有 WebP 编码和预算，本次只在独立目录验证生成，不更新正式发布图。默认着色已采用用户确认的柔和金属曲线，统一源为 `front_end/src/services/medalMaterial.ts`，登记文件为 `front_end/src/assets/medal-templates/coloring.json`。若采用矢量重绘，必须保留已同意的主体与质感，不以文件格式要求再次简化成抽象图标，也不对位图纹理做自动描摹。

主符号、辅助标记、数字和状态各自可复用；不按每个成绩门槛、每种颜色导出整张图片。采用固定视图框和少量路径，必要时提供 32px 专用简化构图。数值继续使用可本地化的文本，处理 Sub、小数和较长 STNB 数值的空间。

增加用途参数以区别行首、阶梯节点和紧凑展示。行内节点的完整门槛放在图标下方，避免 32px 图案内外重复堆叠数字；个人资料栏和名字提示按各自空间保留必要的数字标牌。已获得图形和目标预览使用同一门槛到颜色的映射，显示状态另行叠加。

行内展开后会同时显示更多图形。图形路径和底图应按系列共享，重复节点不复制资源文件、不发起独立换色网络请求；将整页全部阶梯的加载和渲染增量也列入检查，不能只验证六枚佩戴。

若最终选择位图，保留每系列一张可着色底图与独立遮罩，通过统一生成脚本输出透明 WebP；不继续依靠识别金色像素来推断哪些区域需要换色。只有实际采用这一方案时才改造位图生成流水线。

现有单图 8KiB、全库 160KiB、六枚底图保守上限 44KiB 的预算继续作为约束。采用 SVG 或内联图形时，同时统计实际加载的图形、样式及脚本增量，不能用「没有图片请求」掩盖整体体积增长。更新资源版本或文件名，验证旧缓存不会留下旧图案。

### 第一阶段 制作全部基础模板供检阅

历史参考：[17 枚 v2 模板及检阅说明](./artwork-drafts/v2/README.md)、[原图对照预览](./artwork-drafts/v2/index.html)与[逐枚检阅清单](./artwork-drafts/v2/review.json)。v2 和 v1 均仅保留作版本记录，当前采用下方已确认的 v3。

最新交付：[17 枚去外框模板](./artwork-drafts/v3/README.md)、[全套总览及 v2／去框对照](./artwork-drafts/v3/index.html)和[逐枚检阅清单](./artwork-drafts/v3/review.json)。编号沿用 01 至 17；全套已同意并保存到正式源模板目录。旧源图及 SHA256 清单保留于 `artwork-drafts/original-templates/`，尚未进入成绩配色和正式接入阶段。

覆盖当前全部 17 个系列，每个系列至少提供一枚可单独查看的基础模板，不能只交付四个主图形后直接进入正式实施：

- 能力系列共 10 枚：破境、神速、通明、盲扫破境、盲扫神速、盲扫通明、盲扫精工、标旗精工、三阶盲扫精工、三阶标旗精工。

同族模板可以复用主符号，但 NF／FL／三阶的完整构图均须实际展示供检阅。未来尚未开放的系列不在本轮增加模板。

交付内容包括：

1. 每枚独立模板源图及其原图来源、编辑提示词记录，检阅版本集中放在 `docs/medal/artwork-drafts/v3/`，用户同意后同步到正式源模板目录，与正式发布资源隔离。当前为透明 PNG 原图编辑稿，不伪装成可编辑路径的 SVG。
2. 标注系列名称的全量总览，以及 32、40、48、64、72px 实际尺寸对照；同时提供放大图方便检查构图。
3. 原版／新版并排、灰度及浅深背景预览，便于判断核心是否保留、不同系列的辨识度和透明边缘。
4. 一份逐枚清单，记录模板文件、版本、用户反馈及「待检阅／需修改／已同意」状态，初始全部为待检阅。

预览中的系列名称用于检阅，不烘焙到图形中。阶段完成后在回复中展示预览和文件入口，等待用户检阅。

### 检阅节点 用户同意后继续

第一阶段交付后停止后续美术实施，等待用户明确表示同意模板并继续。提交预览、完成自检、没有收到回复或本计划本身均不算同意。

用户提出修改时，只修改对应基础模板并重新提供检阅。用户只同意部分模板时，记录具体范围；未同意的模板及其衍生配色、资源替换和页面接入继续等待，不将局部同意扩展为全套同意。

本节点来自用户对本任务的明确要求。后续阶段以用户实际同意的范围为准，不自动新增其他强制审批节点。

### 第二阶段 制作成绩配色与档位映射

当前最新交付：[柔和金属与逐阶段自定义 v5](./artwork-drafts/time-color-accessible-v5/README.md)与[离线 HTML](./artwork-drafts/time-color-accessible-v5/exports/time-color-accessible-preview-offline.html)。以深蓝／中蓝／浅紫／浅橙／中红替代前两轮默认推荐，覆盖初级 time 全部 11 档；分组仍为 Sub20／15／12、Sub10／8、Sub6／5、Sub4／3、Sub2／1，边界待审阅。支持五档及逐门槛设色、保存和导入导出。旧 time-b-color-v1 保留历史记录。

仅在用户同意基础模板并授权继续后开始。以同意的版本为基础制作各成绩色档，补全一次性、资历和未获得状态的独立颜色规则；候选五色方案仍需结合模板效果完善。

编制所有现有门槛到色档的映射，制作一条完整 12 档阶梯的并列预览，并覆盖初／中／高低中高成绩、NF／FL 和三阶短阶梯。新建统一展示配置，例如 `front_end/src/services/medalAppearance.ts`，维护图形、玩法标记和门槛到色档的映射，核对实际定义覆盖率。

### 用户自定义配色

共享偏好服务已实现于 `front_end/src/services/medalPalette.ts`，新版审阅页直接引用。配置由版本、五个色档颜色和按 `code + stage` 保存的精确门槛覆盖组成，优先精确覆盖，再查已审阅的色档映射。stage 是实际门槛，不是档位序号；无映射门槛回退中性，不猜测最高档。偏好仅影响当前观看者，不修改被查看玩家数据、成绩、规则或难度。

正式接入后在“设置 → 外观 → 勋章配色”提供五档 `BaseColorPicker`、HEX、单档和全部恢复、JSON 导入导出，以及可选的逐门槛高级覆盖。通过响应式偏好同时更新勋章页、佩戴区和名字提示，不增加逐玩家网络请求。存储键 `medal-appearance-colors-v1`；存储失败明确提示，导入完整校验后原子替换，不把预览生效冒充保存成功。

本轮原型只对全金色 Time 主体使用运行时明暗着色；正式接入含 NF 副章等的模板前，必须补充可着色层／遮罩，避免固定色副章被整图换色。新方案定稿、其余系列门槛映射和着色层完成后再切换生产渲染组件。

### 第三阶段 改造渲染并接入页面

## 验收标准

### 基础模板交付验收

- 全部 17 个现有系列均有独立模板、名称和文件入口，NF／FL／三阶变体无遗漏。
- 主体、组合关系和材质与原图可对应，不能用新的象征物取代原图核心；32px 下仍需辨认主轮廓，浅深背景下边缘清楚。
- 检阅预览使用实际尺寸，放大图与小尺寸图对应同一版本，逐枚反馈和同意范围可追溯。
- 检阅阶段与正式发布资源隔离；本次用户同意后仅同步正式源模板并保留旧源图，正式发布图、运行时组件和各展示入口保持原状。
- 第一阶段完成后等待用户明确同意，才进入其授权范围内的后续阶段。

### 正式接入验收

- 将主系列统一为同一种颜色、隐藏名称后，32px 下仍能凭轮廓和核心符号区分；灰度检查时不依赖颜色区分系列。
- 同系列 12 个档位并列时构图稳定，没有通过层层添加装饰表达升级；相邻同色档依然能通过门槛文字区分。
- 同系列的普通、NF、FL 及三阶可辨识；初、中、高有清楚的非颜色标识，图标和完整称号不会表达相反信息。
- 改变难度不再直接触发铜银金切换；同一定义升级时色档不倒退，精确门槛文本正确。
- 映射覆盖所有当前启用的能力定义及门槛；检查时间降序、数值升序、一次性、三阶短阶梯、未知门槛与未获得状态。
- 三个展示入口对相同 code、stage 得出相同色档，名字提示不增加逐玩家的完整摘要请求。
- 未达档位预览不会显示为已获得或已佩戴；完整阶梯展开后不按每个档位下载新整图。
- 浅深主题下边界、符号、数字和未获得状态清晰；佩戴标记不遮挡符号或被误认为更高成绩档。
- 满足资源预算，保留静态、轻量加载；执行外观映射单元测试、相关组件回归、类型检查及所采用资源格式的检查。
